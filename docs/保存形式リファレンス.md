# StudyTracker 保存形式リファレンス

対象: StudyTracker 3.3.2 / 外部 ViewerPack 0.8.1

## 保存場所と設定の優先順位

- DB の正本は StudyTracker 本体の `config.json` にある `db_path` です。
- 設定ファイル: `%APPDATA%/StudyTracker/config.json`（通常は `C:\\Users\\<ユーザー>\\AppData\\Roaming\\StudyTracker\\config.json`）。
- DB の既定値: `%USERPROFILE%/StudyTracker/study_tracker.sqlite3`。
- ViewerPack は StudyTracker 本体の `config.json` にある `db_path` を受け取り、同じ DB を開きます。Viewer 専用設定を DB 選択元として使用しません。
- Viewer は読み込みに read-only 接続を使い、編集時だけ同じ DB に書き込みます。

## SQLite テーブル

| テーブル | 用途 | 主な形式 |
|---|---|---|
| `sessions` | 学習セッション | `id`, `started_at`, `ended_at`, `active` |
| `segments` | 学習記録の区間 | `id`, `session_id`, `start_at`, `end_at`, `active`, `row_json` |
| `timestamps` | 学習中の位置記録 | `id`, `session_id`, `segment_start_at`, `at`, `location`, `unit`, `subject`, `material` |
| `presets` | 学習区分・科目・教材等のプリセット | `kind`, `parent`, `title`, `docstring`, `sort_order` |
| `aliases` | 学習単位エイリアス | `title`, `docstring` |
| `recent_positions` | 教材ごとの最近の学習位置 | `material`, `position`, `last_used` |
| `events` | セッションイベント | `at`, `event`, `payload_json` |
| `settings` | StudyTracker 設定 | `key`, `value` |
| `viewer_edit_history` | Viewer による編集履歴 | 変更前後の JSON を追記保存 |

## `segments.row_json`

`row_json` は UTF-8 JSON オブジェクトです。現行の正規キーは次のとおりです。

- `date`: `YYYY.MM.DD` 形式の日付文字列
- `category`: 学習区分
- `subject`: 科目
- `material`: 教材
- `position`: 学習位置
- `unit`: 学習単位
- `scope`: 学習予定範囲
- `actual_scope`: 学習実施範囲（Viewer で編集可能）
- `notes`: 備考文字列の配列
- `branch_fields`: 表示上の継承セルを示す整数配列

Viewer は互換性のため `科目` / `科目名`、`学習区分`、`教材`、`学習位置`、`学習単位`、`学習範囲` という日本語キーも読み取ります。ただし新規保存・編集時の正規形式は英語キーです。移行の際に元データを破壊しないでください。

## 日時・タイムゾーン

- `sessions` / `segments` / `timestamps` の日時は ISO 8601 文字列です。
- タイムゾーン付きの値を推奨します。タイムゾーンがない既存値は Viewer では日本標準時（UTC+09:00）として解釈します。
- `segments.start_at` は開始日時、`segments.end_at` は終了日時で、終了は開始より後である必要があります。
- `timestamps.segment_start_at` はタイムスタンプが紐づく区間の開始日時です。区間開始を編集すると関連値も更新します。

## 科目が「未設定」になる場合

1. StudyTracker 本体と Viewer が同じ `config.json` の `db_path` を参照しているか確認します。
2. `segments.row_json` の JSON に `subject` または互換キー `科目` / `科目名` があるか確認します。
3. 科目が `timestamps.subject` にだけ存在していても、区間記録の科目には自動補完しません。記録の正本は `segments.row_json` です。
4. JSON が壊れている場合は、先に DB のバックアップを作成してください。

## バックアップと同時利用

- DB を直接編集する前に StudyTracker を終了し、SQLite ファイルをコピーしてください。
- Viewer の編集履歴は同じ DB の `viewer_edit_history` に追記されます。これは通常 UI から変更・削除できませんが、DB ファイルを直接改変する攻撃を防ぐ暗号学的な監査証跡ではありません。
- StudyTracker と Viewer を同時利用してロックエラーが出た場合は、書き込み完了後に再試行してください。

## ViewerPack 追加パッケージの起動

```powershell
python .\main.py --viewer
python .\main.py --viewer-zip "E:\path\StudyTrackerViewerPack_v0.8.1-StudyViewer.zip"
```

- StudyTracker 配布 ZIP には `viewer_v0/` を含めません。ViewerPack は別 ZIP として配布します。
- 既定の `ViewerPackPath` は StudyTracker root 配下の `StudyTrackerViewerPack_v0.8.1-StudyViewer.zip` です。
- 推奨命名規則は `StudyTrackerViewerPack_vx.x.x-<description>.zip` です。
- 「設定」→「使用ディレクトリ・ViewerPack設定」から設定ディレクトリ、DB、ログ、エクスポート先、ViewerPackPath を確認・編集できます。アプリ root は実行ファイルの場所に固定です。
- 起動時に ZIP の内容を検証して一時ディレクトリへ展開します。ViewerPack の独自 DB パス設定は使用せず、StudyTracker 本体の `db_path` を渡します。


## パス設定（StudyTracker 3.3.2）

標準の `%APPDATA%/StudyTracker/config.json` に保存される主な設定キー:

| キー | 用途 |
|---|---|
| `config_dir` | 実際の設定ファイルを置くディレクトリ。標準位置には移動先を追跡するブートストラップ設定も保持 |
| `db_path` | StudyTracker と ViewerPack が共有する SQLite ファイル |
| `log_dir` | アプリケーションログの保存先 |
| `export_dir` | CSV/XLSX/ログ出力ダイアログの既定ディレクトリ |
| `ViewerPackPath` | 起動する ViewerPack ZIP の絶対パス |

パスを変更する前に、アプリを終了し、DB ファイルをバックアップすることを推奨します。`db_path` を変更した場合、別の既存 DB を指定するとそちらが開かれます。元 DB のコピーを作成する場合は、設定画面の確認に従ってください。


## パス設定の一本化（3.3.2）

DB パスは「設定」→「使用ディレクトリ・ViewerPack設定」の `db_path` 欄だけで管理します。旧「データ保存場所」設定は廃止しました。ViewerPack は独自の DB 選択・設定ファイルを持たず、本体から `database_path` として渡された DB のみを開きます。ViewerPack 起動時に `database_path` が渡されない場合は起動エラーにし、環境変数や独自 DB 設定へのフォールバックは行いません。
